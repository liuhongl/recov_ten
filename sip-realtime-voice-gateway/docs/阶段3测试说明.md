# 阶段 3 测试说明：音频格式转换

## 背景

阶段 3 的目标是验证电话侧音频和模型侧音频之间的格式转换是否可靠。

当前电话链路进入网关的是 FreeSWITCH 已经解码后的裸 PCM：

```text
pcm_s16le / 8000 Hz / mono / 20ms / 320 bytes
```

而实时语音模型常见格式是：

```text
输入：pcm_s16le / 16000 Hz / mono
输出：pcm_s16le / 24000 Hz / mono
```

所以第三阶段必须先把以下能力做成纯函数并单测通过：

```text
8k PCM  -> 16k PCM
24k PCM -> 8k PCM
PCM 8k  -> PCMA
PCMA    -> PCM 8k
任意裸音频 -> 20ms 固定帧
```

## 已实现模块

核心文件：

```text
app/audio_codec.py
```

主要函数：

```text
pcm_s16le_frame_bytes(sample_rate, frame_duration_ms=20)
pcm_s16le_to_samples(pcm)
samples_to_pcm_s16le(samples)
resample_pcm_s16le_mono(pcm, source_rate, target_rate)
split_audio_frames(audio, frame_bytes, pad_last=False)
pcm_s16le_to_pcma(pcm)
pcma_to_pcm_s16le(pcma)
```

## 转换策略

上采样使用线性插值：

```text
8k PCM -> 16k PCM
```

下采样使用窗口平均：

```text
24k PCM -> 8k PCM
```

PCMA 使用 G.711 A-law 编解码逻辑，当前用于离线验证和后续真实 SIP Trunk 边界准备。本地第二、第三阶段仍然让 FreeSWITCH 负责 RTP/PCMA 层，网关热链路接收的是 PCM。

- 24k -> 8k 重采样后时长不漂移。
- PCMA 已知样本编码结果。
- PCMA 往返后帧大小保持正确。
- FreeSWITCH media echo 支持 `resample_16k_roundtrip`。

## 电话链路重采样回声测试

启动方式：

```powershell
cd <repo>\sip-realtime-voice-gateway
$env:FREESWITCH_ECHO_MODE = "resample_16k_roundtrip"
python -m app.main --config configs/local.example.toml
```

链路：

```text
MicroSIP
  -> FreeSWITCH 9199
  -> sip-realtime-voice-gateway
  -> 8k PCM 上采样到 16k PCM
  -> 16k PCM 下采样回 8k PCM
  -> FreeSWITCH
  -> MicroSIP 播放回声
```

通过标准：

```text
用户拨打 9199 后，说话仍能听到自己的回声。
```
