# 阶段 4 测试说明：实时模型离线接入

## 背景

阶段 4 的目标是先验证新网关能独立连接端到端实时语音模型，不接电话热链路。

从第一性原理看，阶段 5 要把电话音频实时送给模型并把模型音频播回电话端。阶段 4 先把其中“模型侧闭环”单独拿出来验证：

```text
本地 16k PCM 测试音频
  -> Qwen-Omni-Realtime WebSocket
  -> 模型识别和回复
  -> response.audio.delta
  -> 本地 24k PCM / WAV 文件
```

如果这一段不通，后面接 FreeSWITCH 只会把故障面扩大。

## 官方协议要点

当前实现按阿里云百炼 Qwen-Omni-Realtime WebSocket 协议处理：

```text
连接地址：wss://dashscope.aliyuncs.com/api-ws/v1/realtime?model=<model>
鉴权：Authorization: Bearer <DASHSCOPE_API_KEY>
会话配置：session.update
追加音频：input_audio_buffer.append
提交音频：input_audio_buffer.commit
触发回复：response.create
接收音频：response.audio.delta
回复结束：response.done
```

参考：

- https://help.aliyun.com/zh/model-studio/realtime
- https://help.aliyun.com/zh/model-studio/client-events
- https://help.aliyun.com/zh/model-studio/server-events

## 已实现模块

```text
app/realtime_client.py
app/realtime_probe.py
app/env_loader.py
app/wav_io.py
```

其中：

```text
realtime_client.py：封装 WebSocket 事件、音频发送和服务端事件解析
realtime_probe.py：离线探测命令，输入本地 PCM，输出模型返回 PCM/WAV 和事件摘要
env_loader.py：读取 ai_agents/.env，但不会打印或写入密钥
wav_io.py：把模型返回的 PCM 包装成 WAV，便于人工播放检查
```

`realtime_probe.py` 支持两类输入：

```text
--input-pcm：直接发送 16kHz mono pcm_s16le
--input-wav：读取 WAV，自动转换为 16kHz mono pcm_s16le 后发送
```

## 运行方式

使用裸 PCM：

```powershell
cd <repo>\sip-realtime-voice-gateway
python -m app.realtime_probe `
  --config configs/local.example.toml `
  --env-file ../ai_agents/.env `
  --input-pcm ../ai_agents/agents/integration_tests/asr_guarder/tests/test_data/16k_zh_cn.pcm `
  --output-dir artifacts/stage4 `
  --timeout 90
```

使用 WAV：

```powershell
cd <repo>\sip-realtime-voice-gateway
python -m app.realtime_probe `
  --config configs/local.example.toml `
  --env-file ../ai_agents/.env `
  --input-wav <wav-file> `
  --output-dir artifacts/stage4-user-wav `
  --timeout 120
```

密钥读取顺序：

```text
DASHSCOPE_API_KEY
ALIYUN_DASHSCOPE_API_KEY
```

不要把密钥写进配置文件或文档。

## 本次验证结果

验证时间：2026-05-09

首次使用 `Cherry` 音色失败：

```text
Voice 'Cherry' is not supported.
```

修正：默认音色改为 `Ethan`。

成功结果：

```text
model = qwen3.5-omni-plus-realtime
voice = Ethan
input_audio_bytes = 104770
output_audio_bytes = 184320
output_sample_rate = 24000
output_duration_seconds = 3.84
first_audio_delta_ms = 1281
response_done_ms = 1906
```

模型识别文本：

```text
通过自然语言交互帮助人们进行日程管理。
```

模型回复文本：

```text
好的，请告诉我您想安排什么日程，我马上帮您处理。
```

结论：阶段 4 实时模型离线接入验证通过。当前已经证明新项目可以独立连接 Qwen-Omni-Realtime，发送 16k PCM，本地收到 24k PCM 音频回复并保存为可播放 WAV。

## 本次用户 WAV 样本复测

用户提供本机样本：

```text
C:\Users\Tzk00\Downloads\语音标签示例1.wav
```

原始格式：

```text
pcm_s16le / 24000 Hz / mono / 10.5s
```

探测命令使用 `--input-wav`，网关先把它转换为：

```text
pcm_s16le / 16000 Hz / mono / 10.5s / 336000 bytes
```

再发送给 Qwen-Omni-Realtime。验证结果：

```text
model = qwen3.5-omni-plus-realtime
voice = Ethan
output_audio_bytes = 218880
output_sample_rate = 24000
output_duration_seconds = 4.56
first_audio_delta_ms = 1312
response_done_ms = 2077
```

模型识别文本：

```text
可当他的手触碰到对方的身体时，却感觉一阵冰冷僵硬，那触感不像是活人，更像是尸体。
```

模型回复文本：

```text
天啊，那触感确实太吓人了，换谁都会心里发毛。
```

结论：阶段 4 不只对仓库内置 PCM 样本可用，对用户提供的本地 WAV 样本也可用。后续同事可以替换成自己的 WAV 文件复测，不要求路径与本机一致。
